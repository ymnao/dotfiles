# managed 設定 (起動をゲートする層) の着手基準

- **原則として触らない。** 判断基準は「**壊れたときの復旧に `sudo` が要るか**」。
  要るなら実質一方通行とみなす。このファイルは 2 サイクル連続で起動不能を
  引いている (#302 は `requiredMinimumVersion` の引き上げで Claude Desktop を、
  #297 は `disableSideloadFlags` で Claude Code のプロセスを落とした)。
  **どちらも設定値は仕様どおり正しく、誤っていたのは着手判断のほう**
- **外部サーベイ由来の推奨をそのまま起票しない。** managed 設定の価値は
  「管理者が開発者に policy を外させない」ことだが、この環境は user 1 人・
  管理者も同じ 1 人・マシン 1 台なので守る相手がいない。得られるものと
  「失敗が必ず起動不能になる」対価を天秤に載せてから起票する
- 一次情報で仕様を確かめるのは**前提であって着手理由にはならない**。
  確かめるべきは「入れたら仕様どおり効くか」ではなく
  **「効いたときに何が困るか」**。#297 は前者を全部実測し、後者を公式 docs の
  一文に頼って踏んだ (その一文は実際の影響範囲より過小だった)
- **起動をゲートしない追加は別枠。** `sandbox.credentials` の deny のように
  壊れても起動する種類は、この基準の対象外
- 触ると決めた場合は **ベースライン → 配置 → 検証 → 即戻し** の順を崩さない。
  この順は被害を小さくするだけで、着手判断の誤りは取り消せない
- 配置手順 (`sudo` 4 コマンド)・symlink しない理由・ロックアウトからの復旧経路は
  [docs/ai-operations.md](../../docs/ai-operations.md) §10 を参照
