---

現在のセッションの作業内容を HANDOFF.md に記録し、次のセッションで `/clear` 後に引き継げるようにする。

## Steps

1. 現在の会話を振り返り、以下の情報を整理する
2. プロジェクトルートに `HANDOFF.md` を作成（既存なら上書き）。既存なら書く前に読み、
   下のフォーマットに無い節（「次セッション持ち越しメモ」等の恒久メモ）を消さずに引き継ぐ。
   前のセッションが残した判断は、このセッションの会話からは復元できないため
3. 「目的」と「完了したこと」には今回のセッションの分だけを書き、前回の分は上書きして消す。
   過去のセッションの PR 番号・commit の一覧も書かない (git log・PR 本文・issue に残っている)。
   消す前に、前回の記述から HANDOFF にしか無い次の 4 種類を拾って残る節へ移す
   - 実機で未確認の項目 → 「未完了・次にやること」
   - user の判断とその理由 → 「重要な判断・メモ」
   - コード以外の操作 (user が手で打ったコマンド、issue へのコメント・close) →
     終わっていなければ「未完了・次にやること」、終わっていれば消す
   - 次の作業で使う実測値 (CLI の版、設定の読み先など) → 「重要な判断・メモ」
4. 「未完了・次にやること」に、新しい順番に置き換えられた古い優先順位リストが残っていれば消す。
   消す前に、古いリストにだけ残っている未完了の項目が新しい順番に入っているかを確かめ、
   入っていなければ新しい順番の側に移す。古いリストが残ると、次のセッションがそちらから
   タスクを取るおそれがある

## HANDOFF.md のフォーマット

```markdown
# Handoff

## 目的
<今回のセッションで取り組んでいたタスクの概要>

## 完了したこと
- <完了した作業を箇条書き>

## 未完了・次にやること
- <残っている作業を箇条書き>

## 試したが失敗したこと
- <うまくいかなかったアプローチとその理由>

## 重要な判断・メモ
- <次のセッションで知っておくべき判断事項やコンテキスト>
```

## 注意

- HANDOFF.md はグローバル gitignore（`~/.config/git/ignore`）で除外済み。dotfiles 未セットアップの環境では、プロジェクトの `.gitignore` に `HANDOFF.md` を追加すること
- 次のセッション開始時は「HANDOFF.md を読んで続きをやって」と伝えるだけで引き継げる
- user の確認待ちの項目は、書く前にこのセッションで user が答えていないかを確かめ、答えていれば確認済みとして書き換える（書き漏らすと、次のセッションが同じ確認や警告を繰り返す）
